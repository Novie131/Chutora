# Evidence Analysis（證據導向分析）

**只認證據，不認直覺。** 這套紀律借自反向工程：面對一個不透明的系統，你能講的只有看到的東西，其餘都要標清楚是推的、還是還不知道。拿它來做調查、找根因、審查別人（或自己）的結論。

## 三種斷言，先分清楚

每一句話落地前，先歸到這三類其中一類：

- **觀察**：你實際看到的。檔案第幾行、指令的輸出、測試結果、回傳值。一定附出處。
- **推論**：從觀察推出來的。要寫「根據哪個觀察推的」，讀的人才能檢查這一步。
- **未知**：還沒有證據的。明講「不知道」，不要用推論把它填平。

這個架構最常見的失敗，是把**推論講成觀察**，或把「我靜態讀了程式碼」講成「我實際跑過、看到它這樣跑」。靜態看到的就說靜態看到，不要暗示你觀察到了執行。

## 先概覽，再深入（summary-first）

先拿**最小的概覽**——目錄結構、公開介面、摘要、入口點——形成假設，再針對假設去挖細節。不要一開張就把所有檔案讀完：那既貴又容易迷路。每深入一層，都是為了回答一個具體的問題。

## 調查流程

1. **把問題拆成一張清單**：每個子問題，以及「要什麼證據才能回答它」。
2. **從最小的概覽開始**，順著每個問題從入口追到它的答案。
3. **圍繞一個假設批次操作**，證據出現缺口才擴大範圍。
4. **用對應類型的證據佐證**：行為問題要有執行證據，不能只靠讀碼推測；靜態結論就標成靜態。
5. **收一份 finding ledger**：每個結論 ↔ 出處 ↔ 信心／證據類型 ↔ 還沒確定的部分。下一趟調查能直接接手。

## 回報格式

- 每個結論前面標 `[觀察]`／`[推論]`／`[未知]`，並附出處（檔案:行、指令、連結）。
- 結尾回到問題清單，逐題標：**已答 / 部分 / 未解**，依它實際拿到的證據，不靠印象。
- 負向搜尋要有界：寫「在 X 範圍內找不到 Y」，不要寫成「沒有 Y」。

## 界線

- **「找不到」不等於「不存在」。** 只陳述你搜過的範圍。
- **矛盾的證據兩邊都列**，指出矛盾，不要自己挑一個喜歡的。
- **不確定就說不確定**，不要用肯定的語氣蓋過證據的不足。
