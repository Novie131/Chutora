# Security Review（靜態安全審查）

對**你自己的程式碼**做防禦性安全審查的清單與判準。實際的逐檔審查交給 `security-review` 子 agent 在獨立 context 做；這份 skill 是它（或主對話）照的流程。

## 原則

- 只審授權的碼，只讀不改，不寫可武器化的 exploit。
- 照 evidence-analysis 的紀律：每個發現標清楚是**觀察**到的程式碼，還是**推論**的可利用性。
- 寧可報「可疑待查」，也不要把推論講成確定；但也不要漏報。

## 審查清單（依技術棧取相關項）

- **注入**：使用者輸入有沒有進到 SQL／shell／樣板／正則而沒參數化或轉義。
- **認證與 session**：密碼雜湊方式、token 產生與驗證、session 過期與固定。
- **敏感資料**：明文存放、日誌印出祕密、傳輸未加密、錯誤訊息洩漏內部細節。
- **存取控制**：每個受保護資源有沒有授權檢查；有沒有 IDOR（直接用使用者給的 id 取物件）。
- **設定**：預設憑證、debug／stack trace 對外、CORS／權限過寬、雲端儲存公開。
- **輸出**：HTML／JS 輸出有沒有編碼（XSS）；重導向有沒有白名單。
- **反序列化／XXE**：有沒有反序列化不可信資料、XML 外部實體。
- **SSRF**：由使用者控制的 URL 有沒有限制目的地。
- **相依套件**：跑 `npm audit`／`pip-audit`／`osv-scanner` 等，列已知漏洞。
- **祕密外洩**：`gitleaks` 或 grep 找 hardcoded 金鑰、token、密碼；檢查 `.gitignore` 有沒有排除 `.env`。

## 嚴重度判準

- **critical**：可遠端未授權利用、直接洩漏祕密或 RCE。
- **high**：需要一些條件但影響大（越權、注入在已認證路徑）。
- **medium**：有影響但可達性受限或需鏈結其他問題。
- **low**：強化建議、深度防禦。

## 報告格式

見 `security-review` agent 的回報格式：摘要 → 依嚴重度排序的發現（位置／證據／影響／修補）→ 掃描工具結果 → 未涵蓋與不確定。

## 動態驗證的交接

靜態審查只能到「可疑／很可能」。要**確認**可不可利用，交給 `security-test` 做授權範圍內的動態測試，並把這裡的發現清單當成它的測試重點。
