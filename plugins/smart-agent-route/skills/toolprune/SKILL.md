# Toolprune（工具修剪）

每個載入的工具，它的定義每一輪都會被送進 context，不管你有沒有用到。這招取自 TokenEconomizer：**把長期沒用到的工具關掉，用到時再開回來。** 這份 skill 只做「指認＋建議」，關不關由你決定。

## 它怎麼知道誰沒用到

PostToolUse hook（`post-tool.py`）會把每個被實際呼叫過的工具記進使用記錄：

```
${CLAUDE_PLUGIN_DATA:-~/.claude/hooks}/.tool-usage.json
```

裡面是 `{工具名: {count, sessions, last, ...}}` 與看過的 session 清單。**沒出現在裡面、或 last 已經很舊、sessions 很少的工具，就是沒在用的候選。**

## 流程

1. **讀使用記錄**：讀上面那個 `.tool-usage.json`。讀不到就說「還沒有紀錄，裝好 hook 後多跑幾個 session 再來」，不要硬掰。
2. **列出目前有哪些工具／MCP**：用 `/context` 看目前載入了什麼（尤其 MCP server 和它們的工具，通常是最大宗）。標為 deferred（延後載入）的不佔固定成本，不用動。
3. **比對**：有載入、但在使用記錄裡**跨多個 session 都沒出現**的，列成「可考慮停用」清單。保守一點——門檻用「至少 2 個 session、或至少 5 次沒用到的 session 都沒碰過」，寧可少報。
4. **建議停用方式（可逆）**：
   - 整個 MCP server 沒用到 → 在設定裡停用那個 server（`~/.claude/settings.json` 或專案的 `.mcp.json` / `.claude/settings.json`），而不是刪掉，之後要用再開回來。
   - 工具很多但只固定用幾個的 server → 可用 `enabledMcpjsonServers` / 對應的允許清單只留會用到的。
   - 改前先備份該設定檔，照 route-setup 那套「改前備份、不覆蓋既有值」。
5. **回報**：清楚列出「建議停用什麼、為什麼（多久沒用）、怎麼關、怎麼復原」。**不要自動改設定**，等使用者點頭；使用者要你改時才動手，並告訴他備份在哪。

## 界線

- 只建議、不自動停用。固定成本其實常不是最大開銷（它每輪都吃快取），所以先處理對話長度與輸出，再回來修剪工具。
- 一切可逆：停用只是從設定移除或加進停用清單，一步就能加回來。
- 不確定某工具是不是真的沒用（例如偶爾才用的重要工具），就標出來讓使用者判斷，不要替他決定。
